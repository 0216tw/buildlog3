# BuildLog MVP 개발 계획

## 1. 목적과 기술 구성

이 문서는 `spec.md`에 정한 기능을 어떤 순서로 개발할지 설명합니다. 한 번에 Phase 하나만 진행하고 확인 기준을 통과한 뒤 다음 단계로 넘어갑니다.

| 영역 | 기술 | 역할 |
| --- | --- | --- |
| 화면 | React + TypeScript | 사용자가 보는 화면과 입력 처리 |
| 서버 | Python + FastAPI | 회원, 권한, 기록과 커뮤니티 기능 처리 |
| 실제 서비스 DB | Supabase PostgreSQL | 실제 사용자와 기록 저장 |
| 자동 테스트 DB | SQLite3 | 실제 데이터와 분리된 빠른 테스트 |
| 현재 DB 연결 | Python 내장 `sqlite3` | 수업 전 로컬 개발과 테스트 |
| 이후 DB 연결 | SQLAlchemy | Supabase PostgreSQL 전환 시 검토 |
| 이후 DB 변경 관리 | Alembic | Supabase 전환 시 적용 |

Supabase는 첫 MVP에서 데이터베이스 용도로 사용합니다. React는 Supabase에 직접 접근하지 않고 FastAPI에만 요청합니다. Supabase 연결 비밀값은 FastAPI 환경 변수에만 둡니다.

## 2. 개발 원칙

- `spec.md`를 기능 동작의 최종 기준으로 사용합니다.
- `spec.md`에 없는 사용자 기능은 추가하지 않습니다.
- React에서 버튼을 숨기는 것과 별개로 FastAPI에서도 권한을 검사합니다.
- 비밀번호와 Supabase 연결 비밀값을 코드, 화면, 로그에 노출하지 않습니다.
- 자동 테스트는 기본적으로 독립된 SQLite3에서 실행합니다.
- Supabase 반영 전후에 같은 마이그레이션과 핵심 동작을 확인합니다.
- SQLite3와 PostgreSQL에서 함께 동작하는 데이터 타입과 제약을 사용합니다.
- `.env`, SQLite3 파일, `.venv`, `node_modules`, 로그와 생성 파일은 Git에서 제외합니다.
- Git 초기화와 커밋은 별도 요청 전까지 수행하지 않습니다.

## 3. 예정 프로젝트 구조

```text
buildlog/
├─ backend/
│  ├─ app/
│  │  ├─ main.py             # FastAPI 시작점
│  │  ├─ api/                # API 경로
│  │  ├─ core/               # 설정, 보안, 공통 오류 처리
│  │  ├─ db/                 # SQLAlchemy 연결
│  │  ├─ models/             # DB 모델
│  │  ├─ schemas/            # 입력과 응답 검사
│  │  └─ services/           # 기능과 권한 처리
│  ├─ alembic/               # DB 변경 이력
│  ├─ tests/                 # SQLite3 자동 테스트
│  ├─ alembic.ini
│  └─ requirements.txt
├─ frontend/
│  ├─ src/
│  │  ├─ api/                # FastAPI 요청
│  │  ├─ components/         # 공통 UI
│  │  ├─ features/           # 기능별 UI와 상태
│  │  ├─ pages/              # 화면
│  │  └─ styles/             # 공통·반응형 스타일
│  ├─ package.json
│  └─ package-lock.json
├─ database/                 # DB 설명과 필요한 보조 자료
├─ docs/
├─ .env.example
└─ .gitignore
```

SQLite3 테스트는 기본적으로 테스트마다 임시 DB를 사용합니다. 파일 DB가 필요한 테스트만 `database/` 아래에 만들고 Git에서 제외합니다.

## 5. Phase별 상세 계획

### Phase 0. 개발 시작 전 기준 확인

**진행 상태:** 완료 (2026-10-26)

#### 목표

코드나 패키지를 변경하기 전에 문서, 현재 개발 도구, DB 사용 방식을 확인합니다.

#### 작업

1. `mvp.md`, `PRD.md`, `spec.md`, `plan.md`의 기능과 기술 구성을 비교합니다.
2. `spec.md`를 사용자 기능의 최종 기준으로 고정합니다.
3. 첫 버전 제외 기능을 확인합니다.
   - 이메일 확인, 비밀번호 찾기, 계정 삭제
   - 할 일 마감일과 중요도, 내 할 일 검색
   - 댓글 답글
4. Python, Node.js, npm의 버전과 실행 여부를 읽기 전용으로 확인합니다.
5. Python에서 SQLite3를 사용할 수 있는지 확인합니다.
6. Supabase 프로젝트가 필요한 시점과 환경 변수 항목을 정리합니다.
7. FastAPI 주소, React 주소, 실제 DB와 테스트 DB 설정 이름을 정합니다.
8. 서버·화면·테스트 실행 방법을 적을 `setup.md`의 틀을 준비합니다.
9. Phase별 기능 번호와 확인 항목을 `checklist.md`에 정리합니다.

#### 환경 변수

| 이름 | 용도 | 필요한 시점 |
| --- | --- | --- |
| `DATABASE_URL` | Supabase PostgreSQL 연결 주소 | Phase 2 |
| `TEST_DATABASE_URL` | SQLite3 테스트 DB 주소 | Phase 2 |
| `AUTH_SECRET_KEY` | 로그인 정보 보호 | Phase 3 |
| `FRONTEND_URL` | FastAPI가 허용할 React 주소 | Phase 1 |
| `VITE_API_URL` | React가 요청할 FastAPI 주소 | Phase 1 |

실제 값은 `.env`에만 두고 `.env.example`에는 항목 이름과 비밀이 아닌 예시만 기록합니다.

#### 예상 변경 파일

- `docs/checklist.md`
- 필요 시 `docs/setup.md`
- 코드와 패키지는 변경하지 않음

#### 완료 조건

- 네 문서 사이의 기능과 기술 구성이 일치합니다.
- 로컬 도구와 SQLite3 사용 가능 여부를 알 수 있습니다.
- Supabase를 실제 DB, SQLite3를 테스트 DB로 쓰는 방식이 명확합니다.
- 다음 Phase 전에 사용자가 준비할 항목을 안내할 수 있습니다.

### Phase 2. DB 연결·사용자 모델·첫 마이그레이션

**진행 상태:** 완료 — Supabase 대신 로컬 SQLite3로 대체 (2026-10-26)

#### 작업

현재는 Supabase 수업 전이므로 Python 내장 `sqlite3`로 사용자 저장 기반을 먼저 만들었습니다. Supabase 연결과 SQLAlchemy·Alembic 적용은 이후 DB 전환 단계로 미룹니다.

1. Python 내장 `sqlite3` 연결과 DB 파일 경로를 설정합니다.
2. SQLite3에 사용자 테이블을 만듭니다.
3. 이메일, 닉네임, 안전하게 처리된 비밀번호, 운영자 여부를 저장합니다.
4. 이메일과 닉네임 중복 방지 제약을 SQLite3에 적용합니다.
5. SQLite3 사용자 모델 테스트를 실행합니다.
6. Supabase 연결 주소나 실제 Supabase DB는 아직 사용하지 않습니다.

#### 완료 조건

- SQLite3 사용자 모델 테스트가 통과합니다.
- 로컬 SQLite3 데이터 파일이 생성되고 Git에서 제외됩니다.
- Supabase 비밀값이 React 코드와 Git 대상에 없습니다.

### Phase 3. 회원가입·로그인·닉네임 변경

**진행 상태:** 완료 (2026-10-26)

#### 작업

1. 회원가입·로그인·로그인 상태 확인 FastAPI API를 만듭니다.
2. 이메일, 비밀번호 8~64자, 닉네임 조건과 중복을 검사합니다.
3. 로그인 정보는 화면 JavaScript가 직접 읽지 못하는 안전한 쿠키로 관리합니다.

5. 실패 시 `spec.md`가 정한 입력값만 유지합니다.
6. 로그인하지 않은 사용자의 기록 API와 화면 접근을 막습니다.
7. 계정 설정과 닉네임 변경 API·화면을 만듭니다.
8. SQLite3 자동 테스트와 React 화면 확인을 수행합니다.

#### 완료 조건

- `spec.md` 2장의 모든 확인 항목이 통과합니다.
- Supabase 비밀값을 React가 알지 못합니다.
